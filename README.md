# ترب تعمیر — نمونهٔ نمایشی مقایسهٔ خدمات تعمیر خودرو

نمونهٔ اجرایی یک محصول برای **فهمیدن هزینهٔ تعمیر خودرو پیش از مراجعه**: درخواست مشتری با
کمک هوش مصنوعی روشن می‌شود، پیشنهاد متخصصان قابل مقایسه می‌شود، توافق و هر تغییر هزینه
نسخه‌دار ثبت می‌شود، رسیدها به تأیید صریح مشتری می‌رسند و اگر اختلافی با توافق حل نشود،
حکم لازم‌الاجرای هوش مصنوعی دربارهٔ اقلام و مبلغ همان پرونده ثبت و ابلاغ می‌شود.

> **این یک نصب نمایشی است.** همهٔ حساب‌ها، قیمت‌ها، پرداخت‌ها، پاسخ‌های هوش مصنوعی و
> سوابق «مرجع بازار» نمونه‌اند. هیچ وجهی واقعاً منتقل نمی‌شود، هیچ اتصال زنده‌ای به ترب
> وجود ندارد و این پروژه وابستگی رسمی به ترب ندارد.

---

## پیش‌نیازها

| ابزار | نسخه | توضیح |
| --- | --- | --- |
| Python | ۳٫۱۳ | با [uv](https://docs.astral.sh/uv/) مدیریت می‌شود؛ `uv` خودش نسخهٔ لازم را می‌آورد |
| Node.js | ۲۴ | همراه npm |
| PostgreSQL | ۱۸ | یا با Docker Compose، یا نصب موجود با تنظیم `DATABASE_URL` |

نصب uv: `curl -LsSf https://astral.sh/uv/install.sh | sh`

## اولین راه‌اندازی، گام به گام

ترتیب زیر مهم است: هیچ اسکریپتی به‌جای شما وابستگی نصب نمی‌کند، migration اجرا نمی‌کند یا
داده پاک نمی‌کند.

```bash
# ۰) تنظیمات
cp .env.example .env          # نیازی به کلید مدل نیست

# ۱) پایگاه دادهٔ محلی (یا DATABASE_URL را به نصب موجود بدهید)
docker compose up -d db

# ۲) وابستگی‌های بک‌اند
cd backend && uv sync --locked

# ۳) ساخت schema — همیشه صریح و پیش از اجرای API و worker
uv run alembic upgrade head

# ۴) دادهٔ نمونه (تکرارپذیر؛ دادهٔ موجود را پاک نمی‌کند)
uv run python -m app.seed

# ۵) وابستگی‌های رابط و تولید typeها از قرارداد
cd ../frontend && npm ci && npm run api:types
```

### اجرا

ساده‌ترین راه، اجرای هماهنگ هر سه سرویس است:

```bash
uv run --project backend python scripts/dev.py --with-db
```

بدون `--with-db` از پایگاه ازپیش‌آماده استفاده می‌شود. برای اجرای دستی:

```bash
cd backend && uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
cd backend && uv run python -m app.worker
cd frontend && npm run dev -- --hostname 127.0.0.1 --port 3000
```

- رابط: <http://127.0.0.1:3000>
- مستندات API: <http://127.0.0.1:8000/api/docs>

مرورگر فقط با origin رابط حرف می‌زند؛ Next.js درخواست‌های `/api` را بدون اجرای هیچ قاعدهٔ
محصولی به FastAPI عبور می‌دهد، بنابراین CORS باز یا دسترسی مستقیم به پورت API لازم نیست.

**worker را حتماً اجرا کنید.** مهلت‌ها، داوری، ارزیابی و انتقال بازپرداخت کار اوست؛ بدون
آن، مهلت ۲۴ ساعته هرگز اعمال نمی‌شود.

## ورود با حساب‌های نمونه

ثبت‌نام عمومی، پیامک و شمارهٔ تلفن واقعی وجود ندارد. در صفحهٔ «ورود با حساب نمونه» یکی از
این حساب‌ها را انتخاب کنید:

| نقش | حساب‌ها |
| --- | --- |
| مشتری | `customer-sahar`، `customer-omid` |
| متخصص مرتبط | `specialist-arya`، `specialist-behnam`، `specialist-kaveh` |
| متخصص نامرتبط (عمداً) | `specialist-rasht` (شهر دیگر)، `specialist-heavy` (خودروی دیگر)، `specialist-body` (تخصص دیگر) |
| پشتیبانی | `support-mina` |

نشست و کنترل دسترسی واقعی و سمت سرور است: توکن نشست هش‌شده ذخیره می‌شود، کوکی HttpOnly و
SameSite=Lax است، و هیچ فیلدی در بدنهٔ درخواست نمی‌تواند نقش تازه‌ای بدهد. متخصصان آرشیوی
(`archive-*`) فقط پشتوانهٔ دادهٔ مرجع‌اند و در فهرست ورود نمی‌آیند.

| موضوع | مقدار |
| --- | --- |
| شهر | تهران (محلهٔ نمونهٔ مشتری: تهرانسر) |

خارج از این پوشش، **پیش از هر پرداختی** پیام «فعلاً در پوشش این دمو نیست» نمایش داده
می‌شود. بررسی پوشش رایگان است و هیچ فراخوانی مدل ندارد.

## هوش مصنوعی: نمایشی در برابر واقعی

| | `AI_MODE=mock` (پیش‌فرض) | `AI_MODE=live` |
| --- | --- | --- |
| کلید مدل | لازم نیست | `AI_API_KEY` الزامی است |
| شبکه | هیچ | اتصال به DeepSeek از طریق LangChain |
| پاسخ‌ها | از قواعد و سناریوی نمونه، با برچسب «پاسخ نمایشی» | از مدل پیکربندی‌شده |
| هزینه | صفر | مطابق تعرفهٔ ثبت‌شده |

**اجرای پیش‌فرض کاملاً بدون کلید کار می‌کند.** پاسخ‌های نمایشی همه‌جا برچسب دارند و هرگز
به‌عنوان اجرای مدل واقعی معرفی نمی‌شوند؛ قالب‌های آن‌ها هم عمداً مستقل از خروجی live
نوشته شده‌اند تا قبولی دمو با آزمون مدل اشتباه گرفته نشود.

برای حالت live این متغیرها لازم‌اند و نبودشان خطای روشن می‌دهد (نه بازگشت بی‌صدا به پاسخ
ساختگی):

```bash
AI_MODE=live
AI_API_KEY=...
AI_INPUT_PRICE_PER_MILLION=...     # تعرفهٔ ثبت‌شده به تومان
AI_OUTPUT_PRICE_PER_MILLION=...
AI_TARIFF_RECORDED_AT=2026-09-20
AI_DAILY_COST_CAP_TOMAN=...        # سقف روزانهٔ کل نصب؛ صفر یعنی هیچ فراخوانی live
```

### سقف‌ها و مصرف

هر مرحله حداکثر ۳ نوبت موفق دارد و سهمیهٔ توکن جداگانه‌ای دارد. رزرو بودجه **پیش از**
فراخوانی و در تراکنش انجام می‌شود، بنابراین چند درخواست هم‌زمان نمی‌توانند با هم از سقف رد
شوند؛ هیچ قفل پایگاهی هم در زمان انتظار پاسخ مدل باز نمی‌ماند. فراخوانی پرداخت‌شده‌ای که
پاسخ نامعتبر داد، مصرفش ثبت می‌شود ولی نوبت موفق شخص را کم نمی‌کند. مصرف نامعلوم صفر
فرض نمی‌شود.

بررسی بازپرداخت، بازبینی امتیاز و داوری اختلاف هرکدام بودجهٔ عملیاتی مستقل دارند و به
مشتری صورتحساب نمی‌شوند. با پایان سهمیه، توافق، مشاهدهٔ پیشنهاد و درخواست بازپرداخت
همچنان فعال می‌مانند.

سیاست‌ها (آستانهٔ انصاف، آستانهٔ اختلاف فاحش فاکتور، حداقل سابقه، مهلت‌ها و سقف‌ها) همه در
یک محل تعریف شده‌اند: `backend/app/policy.py`. هر تصمیم، نسخهٔ سیاستی را که با آن گرفته
شده ذخیره می‌کند، پس کالیبراسیون بعدی نتیجهٔ قبلی را بازنویسی نمی‌کند.

## کنترل دمو و سناریوهای زمانی

با حساب پشتیبانی به `/support` بروید. آنجا می‌توانید:

- **ساعت دمو را جلو ببرید** (فقط به جلو). مهلت ۲۴ ساعتهٔ پیشنهاد، ۲ ساعت پذیرش انتخاب،
  ۲۴ ساعت اظهارات اختلاف و ۴۸ ساعت تکمیل شواهد بدون انتظار واقعی آزمون می‌شوند. اختلاف
  ساعت در پایگاه ذخیره می‌شود، پس راه‌اندازی دوبارهٔ سرور آن را به عقب برنمی‌گرداند، و هر
  دو فرایند API و worker آن را می‌خوانند. ساعت سیستم یا فایل‌های بیرون پروژه تغییر
  نمی‌کنند. طول عمر نشست عمداً با ساعت واقعی سنجیده می‌شود تا جلوبردن ساعت شما را از حساب
  بیرون نیندازد.
- **سیاست مبتنی بر مرجع را فعال کنید.** این پرچم فقط سناریوی سیاست داده‌محور را در دمو
  روشن می‌کند؛ نمونه‌های نمایشی هرگز یک گروه مقایسهٔ واقعی را «آماده» نمی‌کنند.
- **شکست بعدی درگاه پرداخت را صف کنید** تا مسیر تلاش مجدد انتقال را ببینید.

## نکته‌های مهم دربارهٔ آنچه ساخته شده

- **قیمت آزاد است.** هیچ کف، سقف یا تأیید هوش مصنوعی شرط ثبت یا انتخاب پیشنهاد نیست. فقط
  نقص ساختاری (فیلد لازم، دامنهٔ نامربوط، نوبت خارج از بازه) مانع ارسال می‌شود.
- **توافق با دو تأیید صریح روی همان نسخه فعال می‌شود.** سکوت تأیید نیست، تأیید نسخهٔ قدیمی
  به نسخهٔ تازه منتقل نمی‌شود، و نسخهٔ فعال قبلی تا دو تأیید نسخهٔ جدید سر جایش می‌ماند.
- **تأیید رسید مجوز افزایش مبلغ نیست.** هزینهٔ اضافی ابتدا باید از مسیر تغییر توافق بگذرد.
  رد رسید مسیر اصلاح یا اختلاف را باز می‌کند و حکم داوری نظر ثبت‌شدهٔ مشتری را عوض نمی‌کند.
- **حکم داوری بدون تأیید مجدد طرفین اعمال می‌شود**، ولی سرویس دامنه آن را پیش از اعمال
  اعتبارسنجی می‌کند: فقط دربارهٔ اقلام مورد اختلاف، بدون قلم تازه یا تکراری، بدون مقدار یا
  مبلغ بیشتر از ادعا، و فقط با شواهدی که واقعاً در ورودی همان بررسی بوده‌اند. مبلغ نهایی
  را کد محاسبه می‌کند. **اجرای حکم یعنی ثبت و ابلاغ نتیجه و مبلغ؛ وصول وجه تعمیر ساخته
  نشده است.**
- **قطعهٔ خریده‌شده توسط مشتری** در «مبلغ کل خدمت» هست ولی دوباره به «قابل پرداخت به
  متخصص» اضافه نمی‌شود.
- **قیمت ترب دستی ثبت می‌شود.** فقط لینک HTTPS با میزبان دقیق `torob.com` پذیرفته می‌شود و
  سرور آن را واکشی نمی‌کند. هشدار «اختلاف فاحش» فقط با حداقل سه قیمت هم‌مبنای تأییدشدهٔ
  پشتیبان و مشاهده‌شده تا ۲۴ ساعت پیش از خرید ساخته می‌شود؛ در غیر این صورت «قابل بررسی
  نیست» نمایش داده می‌شود و هیچ امتیاز منفی ثبت نمی‌شود. قیمت ارزان‌تر از ترب و قطعه‌ای که
  خود مشتری خریده هرگز امتیاز منفی نمی‌سازند.
- **امتیاز شفافیت هزینه** هرگز به‌صورت عدد تنها نمایش داده نمی‌شود: مخرج، دوره و تفکیک
  علت‌ها کنارش می‌آیند و زیر ۵ پروندهٔ قابل ارزیابی اصلاً عددی نشان داده نمی‌شود. کیفیت فنی
  تعمیر از این عدد نتیجه نمی‌شود و هیچ جریمهٔ مالی یا تعلیقی بر پایهٔ آن ساخته نشده است.
- **بازپرداخت**: استحقاق و انتقال دو رخداد مستقل‌اند؛ هر پرداخت حداکثر یک بازپرداخت کامل
  دارد؛ نتیجهٔ ردشده هیچ کار انتقالی نمی‌سازد؛ و تلاش مجدد از همان شناسهٔ انتقال استفاده
  می‌کند.

## آزمون و کنترل کیفیت

```bash
# پایگاه مجزای تست
docker compose --profile test up -d db-test

# بک‌اند
cd backend
uv run alembic -x test=true upgrade head   # فقط بار اول
uv run pytest
uv run ruff check .
uv run mypy app

# رابط
cd ../frontend
npm run typecheck
npm run lint
npm run api:check      # انطباق قرارداد، کد بک‌اند و typeهای تولیدشده
npm run test:e2e       # Playwright، روی پایگاه و پورت‌های مجزای خودش
npm run build
```

هیچ‌کدام از این‌ها به کلید مدل، تماس پولی یا اتصال زندهٔ ترب نیاز ندارند. هر تست pytest
روی schema اختصاصی خودش در پایگاه تست اجرا می‌شود و فقط همان schema را پاک می‌کند، پس
دادهٔ دمو دست‌نخورده می‌ماند. مهلت‌ها با ساعت تزریقی سنجیده می‌شوند، نه با انتظار واقعی.

مسیر `DeepSeekProvider` هم با شبکهٔ شبیه‌سازی‌شده آزموده می‌شود (نه فقط با جایگزینی
`MockAiProvider`): یک درخواست در هر تلاش، پارامتر صریح thinking، نبود retry داخلی در
timeout و 429، ثبت مصرف حتی برای JSON نامعتبر، و نشمردن دوبارهٔ توکن استدلال.

### تغییر قرارداد API

قرارداد از کد تولید می‌شود و typeهای رابط از قرارداد. فایل `frontend/src/lib/api-types.ts`
هرگز دستی ویرایش نمی‌شود:

```bash
cd backend && uv run python -m app.export_openapi
cd ../frontend && npm run api:types && npm run api:check
```

## ساختار پروژه

```
backend/app/
  api/         # مسیرها، وابستگی‌ها، تبدیل خطا، واحد کار هر درخواست
  domain/      # همهٔ قواعد محصول: مالی، نسخه، زمان، مجوز، داوری
  models/      # جدول‌ها و قیدهای پایگاه
  providers/   # آداپتر AI (mock و DeepSeek) و شبیه‌ساز پرداخت
  schemas/     # قراردادهای Pydantic برای API و خروجی مدل
  worker.py    # صف پایدار: مهلت‌ها، داوری، ارزیابی، انتقال
  policy.py    # تنها محل تعریف آستانه‌ها، سهمیه‌ها و مهلت‌ها
frontend/src/
  app/         # صفحات App Router
  components/  # اجزای مشترک رابط
  lib/         # کلاینت API و typeهای تولیدشده
contracts/     # openapi.json تحویلی
```

تصمیم مالی، امتیازدهی و مجوز فقط در بک‌اند اجرا می‌شوند و در TypeScript تکرار نشده‌اند.
بررسی سریع فرم در مرورگر فقط برای تجربهٔ کاربر است؛ سرور همهٔ ورودی‌ها را دوباره
اعتبارسنجی می‌کند.

## محدودیت‌های شناخته‌شده

- پرداخت و بازپرداخت **شبیه‌سازی‌شده‌اند**؛ درگاه بانکی، شمارهٔ کارت و امانت‌داری وجه ساخته
  نشده است. وصول وجه تعمیر هم جزو این نسخه نیست.
- اتصال به ترب فقط لینک جست‌وجو و ثبت دستی است. خزش، API فرضی، موجودی زنده و خرید خودکار
  وجود ندارد.
- «مرجع بازار» در این نصب از دادهٔ نمونه پر شده و مرجع واقعی نیست؛ حالت پیش‌فرض
  `bootstrap` است.
- OCR تصویر، ارسال تصویر به مدل، صوت، RAG و زیرساخت برداری، اشتراک خصوصی متخصص، پیامک و
  اپ بومی پیاده‌سازی نشده‌اند.
- کیفیت حالت live آزموده نشده است؛ قبولی حالت mock معادل آزمون مدل واقعی نیست. برای سنجش،
  `backend/evaluation/cases.json` با ۲۴ پروندهٔ فارسی برچسب‌خورده آماده است.
- تعویض متخصص حداکثر یک بار و فقط پیش از شروع کار ممکن است.
